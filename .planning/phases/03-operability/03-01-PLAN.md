  <files>

  <action>
    1. Define a shared retry predicate and decorator. The predicate and decorator can be defined in `gmail.py` (since gmail.py and labels.py both need it) and imported by labels.py. Alternatively, define them at the top of each module to avoid circular imports — choose the approach that avoids any import cycle.

    **Gmail API retry** (`gmail_retry`):
    - Predicate `_is_retryable_http_error(exc)`: returns True only if `isinstance(exc, HttpError) and exc.resp.status in (429, 500, 502, 503, 504)`. This explicitly does NOT retry 400, 401, 403 (per Pitfall #5 in RESEARCH.md).
    - Decorator using `tenacity.retry` with:
      - `retry=retry_if_exception(_is_retryable_http_error)`
      - `stop=stop_after_attempt(5)`
      - `wait=wait_exponential(multiplier=1, min=2, max=60)`
      - `before_sleep=before_sleep_log(logger, logging.WARNING)` where logger = `logging.getLogger(__name__)`
      - `reraise=True`

    2. **Apply gmail_retry in `gmail.py`**:
       - Add `import logging` and tenacity imports at top
       - Create module-level `logger = logging.getLogger(__name__)`
       - Define `_is_retryable_http_error` and `gmail_retry` decorator in gmail.py
       - Wrap `request.execute()` in `fetch_unread_ids` — extract the execute call into a helper or apply the decorator to a wrapper function `_execute_with_retry(request)` that calls `request.execute()`, then use it for `request.execute()` and `response = request.execute()` calls
       - Wrap `batch.execute()` in `fetch_messages_batch` — similarly use `_execute_with_retry(batch)` or a decorated helper
       - IMPORTANT: Do NOT break the existing function signatures. The retry is internal to the module.
       - IMPORTANT: Keep the SAFETY comment at top. gmail.py remains read-only at the API level — retry doesn't change that.

    3. **Apply gmail_retry in `labels.py`**:
       - Import the retry predicate and decorator from gmail.py: `from email_triage.gmail import gmail_retry` (or re-define locally if import cycle)
       - Add `import logging` and `logger = logging.getLogger(__name__)`
       - Wrap all `.execute()` calls in `list_triage_labels`, `ensure_label`, and `apply_labels` with the retry decorator via a helper function
       - The existing HttpError 409 handling in `ensure_label` must remain intact — retry should wrap the outer execute, 409 is handled by application logic (not retry)

    4. **Apply LLM retry in `classifier.py`**:
       - Define `llm_retry` decorator separately — per RESEARCH.md Pitfall #1, google-genai SDK already retries 429/503 internally
       - Use tenacity only as a coarse outer layer: `stop_after_attempt(3)`, `wait_exponential(multiplier=2, min=4, max=30)`
       - Retry only on non-HTTP transient errors: `retry=retry_if_exception_type((ConnectionError, TimeoutError, OSError))` — NOT on HttpError or API-specific errors (avoid double retry)
       - Wrap the `client.models.generate_content()` call in `classify_email`
       - Add `import logging` and `logger = logging.getLogger(__name__)`

    5. Create `tests/test_retry.py` with tests:
       - Test `_is_retryable_http_error` returns True for 429, 503 HttpError
       - Test `_is_retryable_http_error` returns False for 401, 403, 400 HttpError
       - Test `_is_retryable_http_error` returns False for non-HttpError exceptions
       - Test that `_execute_with_retry` (or equivalent) retries on 503 and succeeds on second attempt (mock execute to fail once then succeed)
       - Test that `_execute_with_retry` does NOT retry on 401 (raises immediately)

    For HttpError mocking in tests, construct HttpError with: `HttpError(httplib2.Response({"status": "503"}), b"Service Unavailable")`

    Run `uv run pytest tests/test_retry.py -v` and `uv run pytest -v` (full suite) to verify no regressions.
