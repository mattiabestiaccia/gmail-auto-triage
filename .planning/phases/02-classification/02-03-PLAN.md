    parser.add_argument(
        "--dry-run",

        help="Classify emails but do not apply labels in Gmail",

    **2. After step 8 (parse and filter), add the classification pipeline:**

    ```
    # 9. Initialize GenAI client (skip if no emails to classify)
    # 10. Load label cache and filter idempotent
    # 11. Classify each email with delay between calls
    # 12. Apply labels (or skip if dry-run)
    # 13. Print classification summary
    ```

    **Detailed implementation for steps 9-13:**

    **Step 9 - GenAI client:**
    ```python
    from email_triage.classifier import create_genai_client, classify_email
    from email_triage.labels import list_triage_labels, ensure_label, apply_labels, is_already_triaged, LABEL_PREFIX, AMBIGUOUS_LABEL
    from email_triage.output import print_classification_summary, print_classification_result
    ```
    Only create the GenAI client if there are filtered emails to classify. Call `create_genai_client()` -- it will fail fast with clear error if GEMINI_API_KEY is not set.

    **Step 10 - Idempotency filter:**
    Call `list_triage_labels(service)` to get the label cache (dict[str, str]). Extract triage_label_ids as `set(cache.values())`. Filter `filtered` emails: for each email, if `is_already_triaged(email, triage_label_ids)` is True, count as skipped. Keep only non-triaged emails for classification.

    **Step 11 - Classification loop:**
    For each email to classify:
    - Call `classify_email(client, email, config.categories, config.classification)`
    - If verbose or dry_run, call `print_classification_result(email.subject, result.categories, result.is_ambiguous, parsed.dry_run)`
    - Track counts: classified (not ambiguous) and ambiguous
    - Add `time.sleep(4)` between LLM calls to respect ~15 RPM free tier limit (per RESEARCH.md Pitfall #3). Skip delay after the last email.
    - Print progress: `print_info(f"Classifying {i+1}/{total}...")` for each email

    **Step 12 - Label application (skip if dry-run):**
    After classification of each email (inside the same loop), if NOT dry_run:
    - If result.is_ambiguous: `ensure_label(service, "_Ambiguous", label_cache)` and apply
    - Else: for each (category_name, confidence) in result.categories, `ensure_label(service, category_name, label_cache)` then collect all label IDs and call `apply_labels(service, email.id, label_ids)` once per email

    **Step 13 - Summary:**
    Replace the existing "Compact summary" section (step 9 in current code) with `print_classification_summary(classified, ambiguous, skipped, parsed.dry_run, elapsed)`. Keep the existing verbose email preview output but move it to within the classification loop (it's now per-email via print_classification_result).

    **Error handling:**
    - Wrap individual email classification in try/except. On error, print_error with the email subject and continue to next email (don't crash the batch). Count errors separately.
    - Handle `google.genai.errors.ClientError` and general `Exception` for LLM failures.
    - The overall try/except for RefreshError and KeyboardInterrupt remains as-is.

    **Important constraints:**
    - Do NOT remove existing CLI arguments (--config, --credentials, --token, --verbose, --max-emails, --window-hours)
    - The fetch pipeline (steps 1-8) stays unchanged
    - `--dry-run` performs real LLM classification but skips `apply_labels()` calls (per user decision)
    - Summary counts are ALWAYS shown (both dry-run and real mode, per user decision)
    - Use `dotenv.load_dotenv()` at the top of main() to ensure .env is loaded before GenAI client creation
