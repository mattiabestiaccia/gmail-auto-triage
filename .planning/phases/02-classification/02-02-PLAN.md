  <behavior>
    Label management operates on Gmail API service object and EmailData.

    Constants:
    - LABEL_PREFIX = "AutoTriage/"
    - AMBIGUOUS_LABEL = "AutoTriage/_Ambiguous"

    Pure logic tests (no mocking needed):

    1. is_already_triaged(email_with_triage_label, triage_ids={"Label_100"}) -> True
    2. is_already_triaged(email_without_triage_label, triage_ids={"Label_100"}) -> False
    3. is_already_triaged(email_with_empty_labels, triage_ids={"Label_100"}) -> False

    API-level tests (mocked Gmail service):

    4. list_triage_labels returns {name: id} mapping filtered to AutoTriage/* labels only
    5. list_triage_labels ignores non-AutoTriage labels
    6. ensure_label returns existing label ID from cache without API call
    7. ensure_label creates parent "AutoTriage" first if not in cache, then creates child
    8. ensure_label creates child label and updates cache
    9. ensure_label handles 409 Conflict by re-fetching label list and returning existing ID
    10. apply_labels calls messages().modify with addLabelIds
    11. apply_labels with multiple label IDs sends all in one modify call

    Cases:
    - is_already_triaged(EmailData(label_ids=["Label_100", "UNREAD"]), {"Label_100"}) -> True
    - is_already_triaged(EmailData(label_ids=["UNREAD", "INBOX"]), {"Label_100"}) -> False
    - ensure_label(service, "Newsletter", {"AutoTriage/Newsletter": "Label_1"}) -> "Label_1" (from cache, no API call)
    - ensure_label(service, "Newsletter", {}) -> creates "AutoTriage" parent, then "AutoTriage/Newsletter", returns new ID
  </behavior>
  <implementation>
    **Create labels.py with:**

    - `LABEL_PREFIX = "AutoTriage/"` -- hardcoded per user decision, NOT configurable
    - `AMBIGUOUS_LABEL = "AutoTriage/_Ambiguous"` -- underscore prefix for alphabetical sorting per user decision

    - `list_triage_labels(service) -> dict[str, str]`: calls `service.users().labels().list(userId="me")`, returns `{name: id}` mapping filtered to labels whose name starts with `LABEL_PREFIX`. This is the initial cache population.

    - `is_already_triaged(email: EmailData, triage_label_ids: set[str]) -> bool`: checks if `email.label_ids` intersects with `triage_label_ids`. Pure function, no API call. Uses set intersection.

    - `ensure_label(service, name: str, cache: dict[str, str]) -> str`: takes a category name (e.g., "Newsletter"), constructs full name (e.g., "AutoTriage/Newsletter"). If full name in cache, return cached ID. Otherwise: (1) check if parent "AutoTriage" exists in cache, if not create it via `labels().create()` and add to cache, (2) create child label via `labels().create()` and add to cache, (3) return new label ID. On `HttpError` with status 409 (conflict), catch exception, re-fetch labels list to populate cache, and return the existing ID. Label visibility: `labelListVisibility: "labelShow"`, `messageListVisibility: "show"`.

    - `apply_labels(service, message_id: str, label_ids: list[str]) -> None`: calls `service.users().messages().modify(userId="me", id=message_id, body={"addLabelIds": label_ids})`. Simple wrapper, single API call per message.

    **Important notes:**
    - Import `EmailData` from `email_triage.models` (label_ids field already exists from Phase 1)
    - Do NOT import or depend on classifier.py -- labels module is independent
    - `ensure_label` mutates the cache dict in place (dict is mutable, caller keeps reference)
    - For 409 handling: `from googleapiclient.errors import HttpError`, check `error.resp.status == 409`
    - Tests use MagicMock for Gmail service, same pattern as tests/test_auth.py and tests/test_gmail.py
  </implementation>
</feature>
