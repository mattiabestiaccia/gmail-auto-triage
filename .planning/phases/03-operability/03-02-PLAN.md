       - Keep `print_classification_result()` and `print_classification_summary()` from output.py for user-facing formatted console output (these are presentation, not logging)
       - IMPORTANT: output.py functions that write to stdout remain for interactive/TTY use. Logging goes to stderr. Both channels coexist.

       **RunStats accumulation** (throughout pipeline):
       - Create `stats = RunStats()` at start
       - Set `stats.total_fetched` after fetching emails
       - Set `stats.skipped_triaged` after idempotency filter
       - In the classification loop:
         - Increment `stats.classified` or `stats.ambiguous` based on result
         - Update `stats.categories[cat_name] += 1` for each classified category
         - Increment `stats.api_calls_llm` per classify call
         - Extract token usage from classify_email response — this requires modifying `classify_email` to return token usage OR extracting it differently. Simplest approach: add `token_usage_prompt` and `token_usage_completion` fields to `ClassificationResult` (populated defensively from response in classifier.py), then accumulate in stats. Alternatively, just track api_calls_llm count and skip per-call token extraction for now if changing ClassificationResult would break too many tests. Choose the approach that minimizes disruption — if adding fields to ClassificationResult, add them with default=0 so existing tests don't break.
         - On exception: increment `stats.errors`, append error detail string to `stats.error_details` (truncated to 200 chars)
       - Set `stats.elapsed_seconds` at end

       **Error resilience** (OPS-03):
       - The per-email try/except already exists in cli.py — KEEP it
       - Log each error with `logger.error(f"Failed to process '{email.subject[:50]}': {exc}")` instead of print_error
       - Continue processing remaining emails after error
       - At end, if errors > 0, log warning with total count

       **Cron-compatible exit codes** (OPS-01):
       - Wrap the entire pipeline in try/except at the top level
       - On success (pipeline completes): `sys.exit(0)` — even if some individual emails errored (OPS-03 says batch continues)
       - On `KeyboardInterrupt`: `sys.exit(130)`
       - On fatal exception (auth failure, config error, etc.): `logger.exception("Fatal error")`, `sys.exit(1)`
       - Remove the existing print-based error handling at the bottom of main()

       **Summary email** (at end, before exit):
       - If `not parsed.no_notify` and `stats.classified + stats.ambiguous + stats.errors > 0` (skip on zero-email runs per RESEARCH.md recommendation):
         - Wrap `send_summary_email(service, stats)` in try/except
         - On success: `logger.info("Summary email sent (ID: %s)", msg_id)`
         - On failure: `logger.warning("Failed to send summary email: %s", exc)` — do NOT raise, do NOT change exit code (per Pitfall #6)
       - If `parsed.dry_run`: skip sending summary email (dry-run should have no side effects beyond LLM calls)
