**models.py** — Create data models:

```python
from dataclasses import dataclass

@dataclass
class EmailData:
    id: str
    thread_id: str
    sender: str
    subject: str
    date: str
    snippet: str
    label_ids: list[str]
```

This is a simple dataclass (not pydantic) because it represents API response data, not validated config.

**config.py** — YAML loading with pydantic validation:

Create pydantic models:
- `CategoryConfig(BaseModel)`: `name: str`, `description: str`, `examples: list[str]` with `field_validator` ensuring `len(examples) >= 1`.
- `FetchConfig(BaseModel)`: `processing_window_hours: int = 24`, `max_emails: int = 100`, `snippet_length: int = 500`, `fields: list[str] = ["subject", "sender", "snippet"]`.
- `AppConfig(BaseModel)`: `categories: list[CategoryConfig]` with validator ensuring at least 1 category, `fetch: FetchConfig = FetchConfig()`.

Create `load_config(path: str) -> AppConfig` function:
- Opens file, catches `FileNotFoundError` -> prints actionable error ("Config file not found: {path}. Create a categories.yaml file — see categories.yaml.example for format.") -> `sys.exit(1)`.
- Parses with `yaml.safe_load()`, catches `yaml.YAMLError` -> prints "Invalid YAML syntax in {path}: {details}" -> `sys.exit(1)`.
- Validates with `AppConfig.model_validate(raw)`, catches `ValidationError` -> prints field-specific errors with location path -> `sys.exit(1)`.
- Returns validated `AppConfig` on success.

Note on CONF-04: No custom prompt template override — prompt will be hardcoded per user decision. Do NOT add any prompt-related fields to the config models.

**categories.yaml** — Example config with 4 categories (Newsletter, Finance, Social, Shopping) per research examples. Each category has name, description, and at least 1 example. Include `fetch:` section with defaults commented out to show available options.

**tests/test_config.py** — Follow TDD approach:
Write tests FIRST, then verify they pass. Tests must cover:
1. `test_load_valid_config` — loads a valid YAML, returns AppConfig with correct categories.
2. `test_category_missing_description` — YAML with category missing description raises SystemExit.
3. `test_category_no_examples` — YAML with empty examples list raises SystemExit.
4. `test_missing_config_file` — nonexistent path raises SystemExit.
5. `test_invalid_yaml_syntax` — malformed YAML raises SystemExit.
6. `test_default_fetch_settings` — YAML without `fetch:` section uses defaults (24h, 100, 500).
7. `test_custom_fetch_settings` — YAML with custom `fetch:` values overrides defaults.

Use `tmp_path` fixture for temporary YAML files. Use `pytest.raises(SystemExit)` for error cases.

Run `uv run pytest tests/test_config.py -v` and ensure all tests pass.
